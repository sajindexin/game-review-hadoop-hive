# 联调记录（第 7 章素材）

**联调双方**

| 角色 | 模块 | 分支 / 位置 | 启动方式 |
| --- | --- | --- | --- |
| 前端页面 + 指标数据 | `steam-review-web`（本案） | `feat/steam-review-web` | `python server.py --port 8066 --agent-base http://127.0.0.1:8000` |
| 检索与问答 Agent | `agent-retrieval`（唐宇杰） | `feat/agent-retrieval` | `python -m src.cli serve --port 8000` |

**联调日期**：2026-11-26　**环境**：Windows 11 / Python 3.13 / Chrome 128

**联调结论：五个步骤全部跑通。** 前端页面不修改页面结构，通过 `server.py` 内的适配层转发到后端
`POST /api/agent/ask`，把 `numbers[]`、`citations[]`、`evidence_status` 映射成页面契约。
后端不可用时自动回退本地规则引擎，页面不白屏（已实测，见文末「降级验证」）。

## 0. 启动（两边都要起）

```bash
# 终端 1：唐宇杰的模块（先构建知识库，只需一次）
cd agent-retrieval
python -m pip install -r requirements.txt
python -m tools.build_knowledge --parquet "<v1 包>/cleaned_reviews.parquet" --out data
python -m src.cli serve --port 8000
# 健康检查应返回 docs=62007

# 终端 2：前端页面，用 --agent-base 指向上面的服务
cd steam-review-web
python server.py --port 8066 --agent-base http://127.0.0.1:8000
# 页面入口：http://127.0.0.1:8066/index.html
```

前端启动日志会打印当前问答后端：

```

接口：       POST http://127.0.0.1:8066/api/ask
数据：       12 款游戏 / 26 个版本
问答后端：   检索 Agent http://127.0.0.1:8000（不可用时自动回退本地规则引擎）
```

![Steam 原文页](screenshots-joint/j5-steam-original.png)

**实际结果**

故意停掉后端（Ctrl+C 掉 8000 端口的服务），再问一句：

页面不白屏、不报错。

## 联调中修复的两个问题（写进第 7 章能体现工作量）

**1. 量纲不一致**
后端 `numbers[].value` 在 `unit="%"` 时是 0~1 的比例（`0.9745`），`unit="pp"` 时是百分点数值（`0.9638`）。
直接映射会让页面显示 `0.97%`。适配层按 `unit` 分支处理：`%` 且 ≤1 时乘 100。

**2. delta 四舍五入口径差 0.01**
后端给 `+0.96 pp`（0.9638 四舍五入），页面按 `98.42 − 97.45` 算是 `+0.97`。
统一为「用 before/after 差值重算」，两边都显示 `+0.97`，报告数字不会打架。
