# 联调记录：选游戏版本 → 查指标 → 提问 → 看引文 → 点原文

- 联调日期：2026-11-26
- 联调对象：前端页面 `steam-review-web`（本案）+ 问答接口 `POST /api/ask`（`server.py` 提供的实现，接口契约与 Java Servlet 一致）
- 联调环境：Windows 11，Chrome 128，服务地址 `http://127.0.0.1:8021`
- 数据版本：`data/index.js`（12 款游戏 / 26 个版本）+ `data/patches/*.js`，由 `tools/export_web_data.py` 从 4,884,580 条清洗评测导出

## 0. 启动

```bash
cd steam-review-web
python server.py --port 8021
# 页面入口：http://127.0.0.1:8021/index.html
# 问答接口：POST http://127.0.0.1:8021/api/ask
```

服务启动即输出游戏数、版本数与两个入口地址，静态页与接口同源，免配 CORS。

## 1. 选游戏和版本

页面 `index.html` 顶部为焦点更新与游戏胶囊墙，下部为 26 个版本的一览表。

1. 在筛选框输入「星露谷」，游戏墙收敛到 1 款，版本表收敛到 3 个版本（1.4 / 1.5 / 1.6）。
2. 点击版本表中的「1.5 内容更新」，跳转 `patch.html?id=sdv_20201221_15`。

![筛选](screenshots/02-store-filter.png)

**实际结果**：筛选后 1 款游戏、3 个版本；1.5 版本行显示 2020.12.21 发布，更新前 97.5%、更新后 98.4%、+0.97 pp。

## 2. 查指标

版本页「概览」标签展示四张统计卡、推荐率折线、每日评论量柱状图、三阶段对比与分语种变化。

![版本概览](screenshots/03-patch-overview.png)

**实际结果**

| 指标 | 数值 | 来源 |
| --- | --- | --- |
| 更新前 14 天推荐率 | 97.45%（1,021 条） | `分阶段统计.csv` |
| 更新当日推荐率 | 100.00%（253 条） | 同上 |
| 更新后 14 天推荐率 | 98.42%（4,802 条） | 同上 |
| 净变化 | +0.97 pp | 98.42 − 97.45 |
| 窗口有效评论 | 6,076 条（其中 4,597 条正文长度 40–1400，进入可分析样本池） | Hive 统计 / 导出脚本计数 |
| 分语种 | 简中繁中 93.51%→93.90%（+0.39）；英语 98.33%→99.22%（+0.89） | `分阶段统计.csv` |
| 评论量峰值 | 2020-12-22，551 条，推荐率 98.37% | `逐日统计.csv` |
| 推荐率低点 | 2020-12-15，92.13% | 同上 |

> 口径说明：6,076 与 4,597 的差额来自样本池过滤（正文太短或过长的评测不进抽样池），页面上两处数字均标注了口径，避免和报告里的 Hive 统计混淆。

            "delta_pp": 0.97, "window_reviews": 6076, "pool_reviews": 4597},
  "citations": [
    {"review_id": "81959365", "language": "zh-Hans", "voted_up": true, "votes_up": 6314,

五类问题的识别结果（`intent`）：整体口碑 `overall`、语种差异 `language`、改动条目 `items`、趋势峰值 `trend`、负面引文 `negative`，各返回 3 条引文，全部带 `url`。

![改动与引文](screenshots/04-patch-items-citation.png)

**实际结果**

| --- | --- | --- |
| S15_05 本地分屏合作 | 17 | 4 |
| S15_04 海滩农场 | 11 | 4 |
| S15_01 姜岛探索 | 4 | 4 |
| S15_02 金核桃解锁 | 0 | 0 |

金核桃 / 火山地牢在窗口内确实没有评测正文提到（全语料 40 万条里「金核桃」仅 73 条、且都不在 2020-12-07 至 2021-01-04 窗口内），页面显示 0 并提示「该改动在窗口内没有被评测正文提到」，不做补数。

## 5. 点开原文

引文与评测样本里每条都带「在 Steam 打开原文 →」，链接形式为
`https://steamcommunity.com/profiles/<steamid>/recommended/<appid>/`。

以语种问答返回的第一条引文为例，点击后打开的真实 Steam 页面：

![Steam 原文](screenshots/08-review-original.png)

页面标题为「Steam Community :: HuskiGirl :: Review for Stardew Valley」，正文与页面引文完全一致（`If you want to play a farming simulator… Likes / –Aesthetically pleasing / –Co-op (online and split-screen) …`），发布日期 2020 年 12 月 31 日，推荐状态「推荐」，与接口返回的 `voted_up: true`、`created_at: 2020-12-31` 对得上。

> 说明：Steam 同一用户对同一游戏只有一条评测，因此用 `steamid + appid` 即可定位到该条评测，无需 `recommendationid`。链接会 302 跳转到用户的公开自定义域名（如 `/id/huskhusk/recommended/413150/`），最终页面 200。

## 联调结论

- 五个步骤全部跑通，页面与接口同源，无跨域问题。
- 接口不可用时前端自动回退到本地规则引擎（`file://` 直开即此模式），页面不白屏。
- 已知差异：接口 `stats.window_reviews` 为 Hive 口径 6,076，`pool_reviews` 为样本池 4,597，两者在页面和文档中均已标注，报告里引用指标时请用 6,076 这一组。
- 待补：与唐宇杰的 Java Servlet 实现对接时，只需把他的服务地址填进 `assets/ask.js` 的 `S.backendBase`，接口字段按本文档的契约对齐即可，无需改页面结构。
