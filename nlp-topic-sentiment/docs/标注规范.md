# 主题—情感标注规范（ABSA · 两层标签）

> 模块：中文 NLP 与专题统计　数据版本：游戏评论清洗成果 v1
> 适用：人工标注集 + RBT3 两层训练金标构造
> 两层：第一层 通用主题(11类) + 第二层 具体更新条目(75项，游戏特定)

## 1. 任务定义

对每条中文评论，做两层标注：
1. **第一层**：识别谈到了哪些**通用主题（aspect）**，逐主题判情感；
2. **第二层**：识别谈到了该游戏的哪些**具体更新条目（item）**，逐条目判情感。

每条评论可对应多个主题、多个条目，各自独立打标，情感可以相反。
第二层只在**该评论所属游戏的候选条目**里选（如星露谷可选"姜岛探索"，CS2 则不可）。

**核心示例**（务必理解）：

| 评论 | 标注结果 |
|---|---|
| 新关卡好玩，但联机老掉线 | 内容/玩法=正向；联机/服务器=负向 |
| 画面很棒，剧情也不错，就是优化太差老是闪退 | 画质美术=正向；剧情=正向；性能优化=负向 |
| 好玩，爱玩，音乐美术及战斗无敌 | 内容=正向；音效=正向；画质=正向；操作=正向 |
| 姜岛探索好玩，但八人联机老掉线 | **第一层**：地图关卡=正、联机=负；**第二层**：S15_01姜岛探索=正、S16_04八人联机=负 |

## 2. 主题体系（11 类）

| ID | 中文名 | 判定范围（谈以下内容就标此主题） |
|---|---|---|
| `content` | 内容/玩法 | 新关卡/新角色/新武器/DLC、玩法、内容量、可玩性、自由度、耐玩 |
| `level_design` | 地图/关卡设计 | 地图设计、关卡设计、空气墙、引导/指引、探索、具体章节质量（如"花果山很敷衍"） |
| `multiplayer` | 联机/服务器 | 联机、多人、服务器、掉线、延迟、匹配、组队、开黑、合作 |
| `graphics` | 画质/美术 | 画质、画面、美术风格、建模、光影、贴图、画风、风景 |
| `performance` | 性能/优化/BUG | 优化、卡顿、掉帧、闪退、BUG、崩溃、帧数、配置、加载、白屏 |
| `story` | 剧情/叙事 | 剧情、故事、叙事、结局、台词、角色塑造、碎片化叙事 |
| `controls` | 操作/手感/难度 | 手感、打击感、操作、闪避、精防、难度、BOSS战、战斗系统 |
| `monetization` | 付费/氪金 | 氪金、内购、价格、皮肤、性价比、"值不值"、智商税、涨价 |
| `cheating` | 外挂/反作弊/公平 | 外挂、作弊、反作弊、封号、平衡性、炸鱼、公平性 |
| `audio` | 音效/音乐 | 音乐、音效、配音、BGM、配乐、声音 |
| `community` | 运营/社区/官方 | 官方、运营、客服、更新频率、社区环境、厂商（育碧/V社） |

## 3. 情感极性（3 类）

| 标签 | 含义 | 判定要点 |
|---|---|---|
| `positive` | 正向 | 明确夸奖：好玩、优秀、爽、精美、流畅、推荐、爱玩 |
| `negative` | 负向 | 明确批评：垃圾、无聊、卡顿、敷衍、掉线、坑钱、劝退 |
| `neutral` | 中性/中性陈述 | 提到主题但无明确褒贬，如"这个游戏有联机模式" |

**否定与转折规则**：
- 否定翻转："不好玩"=负向，"不难玩"=正向。
- 转折取后：出现"但/不过/就是/可惜"时，真实评价通常在转折之后。
- 就近绑定：情感词绑定到**同一子句**里的主题；跨子句不混。

## 4. 边界与争议处理

1. **只提到游戏整体，无具体主题**（如"神作""垃圾游戏"）→ 不标任何主题（此时整体情感用 `voted_up` 衡量）。
2. **一个词属于多个主题**（如"新地图"）：描述内容新颖 → `content`；评价地图设计好坏 → `level_design`。
3. **反讽/阴阳**（如"真是个好游戏呢"，实为差评）→ 按字面无法判断，标 `neutral`，并在备注注明。
4. **无法判断的俚语/黑话** → 标 `neutral`，备注里写清，供规则词典迭代。

## 5. 标注文件格式

本次交付的 `annotation_tasks.csv` 已内置 240 条语义金标，无需再手动标注。若后续需要新增标注，可在本地用点选工具导出后按 `merge_gold.py` 的格式合并。
`annotation_tasks.csv` 中有两列需要填写：

**5.1 第一层 `gold_aspects_json`** — JSON 数组：

```json
[{"aspect":"content","sentiment":"positive"},{"aspect":"multiplayer","sentiment":"negative"}]
```
- `aspect` 为第 2 节 11 个 ID 之一；`sentiment` 为 positive/negative/neutral。
- 无主题填 `[]`。

**5.2 第二层 `gold_items_json`** — JSON 数组：

```json
[{"item_id":"S15_01","sentiment":"positive"},{"item_id":"S16_04","sentiment":"negative"}]
```
- `item_id` 必须从该任务 `cand`（候选条目）里选，每款游戏 4~19 项，见 `data/taxonomy/items_enriched.json`。
- **只有评论明确提到该具体改动才标**：如"姜岛很好玩"标 S15_01；只说"新内容好玩"不标具体条目（标第一层 content 即可）。
- **跨游戏不算**：CS2 评论里出现"姜岛"不标 S15_01。
- **同义改述也算**：评论没用官方原词但明显在说该改动（如"岛上的农场"指姜岛），应标。
- 无具体条目填 `[]`。

争议的评论在 `annotate_note` 写明。

## 6. 质量控制

- 标注前先标注 20 条试标，对齐口径后再批量。
- 抽取 10% 做双人交叉标注，计算 Cohen's Kappa，目标 ≥ 0.7。
- 分歧样本集体讨论后写入 `gold_samples.csv`。
