# 设计说明

## 1. 要解决的问题

版本页上的「问这个版本」需要同时回答三类问题，而且**答案必须能核对**：

| 问法 | 需要的证据 | 数据来源 |
|---|---|---|
| 推荐率降了多少？ | 数字 + 样本量 | 26 个版本的窗口指标表 |
| 这次更新改了什么？ | 官方条目 + 公告链接 | `items.jsonl` / `patches.jsonl` |
| 玩家怎么评价新地图？ | 玩家原话 + 出处 | v1 全量评测的窗口样本 |

难点不在“生成一句话”，而在**不编**：数字要能追到指标表，原话要能点回 Steam。
所以本模块把生成压到模板层，把不确定性全部放进检索层，并用“实体词门槛”兜底。

## 2. 数据流

```
cleaned_reviews.parquet (4,884,580)
        │  只扫 26 个版本窗口（发布日 ±14 天）
        ▼
窗口语料 62,007 条 ──► BM25 倒排索引 (178k terms)
        │            └─► 向量矩阵 (512d, hash 兜底 / BGE 可换)
        │
窗口内已复核可引用关联.jsonl (469 条) ──► 已复核引文库 + 独立 BM25
        │
items.jsonl / patches.jsonl ──► catalog.json（版本、条目、指标、公告链接）
更新前后对比.csv ─────────────┘
        │
        ▼
Agent：意图 → 工具 → 证据分级 → 模板作答 → {answer, numbers, citations, links}
```

构建脚本 `tools/build_knowledge.py` 一次跑完，约 10 秒；产物约 40MB，全部可重建。

### 语料抽样策略

窗口内评测有几十万条，全量建索引没有必要。规则：

1. **提到官方改动的评测优先全收**（按条目标题双字词 + 人工别名匹配，每版本最多 1,200 条）；
2. 每个阶段（更新前 / 发布当天 / 更新后）再随机保留最多 900 条普通样本；
3. 按 `review_id` 去重，正文截断到 1,000 字。

这样既保证“姜岛”“挂件”这类稀有提及不会因随机抽样丢失，又控制了索引规模。

## 3. 检索

### 3.1 分词

不引入 jieba（部署环境不一定有）。中文取「单字 + 相邻双字」，英文取连续字母数字。
单字只参与 BM25 召回，**证据门槛不用单字**，避免“挂”“水”这类字把噪声带进来。

### 3.2 打分

```
score = 0.7 * normalize(BM25(q, mask)) + 0.3 * normalize(cos(q_vec, doc_vec))
```

- `mask` 先按版本、语种、阶段、好评/差评过滤；
- 条目明确时，命中该条目别名的评测乘 1.25 加权；
- 取前 60 个候选后做**实体词门槛**：候选正文必须包含问题里的高 IDF 实体词
  （或条目别名），否则丢弃；一条都不剩就返回 `no_quotes`。

`_key_terms` 里维护了一份疑问/功能词表（`怎么`、`为什么`、`评价`、`推荐率`…），
它们不参与门槛——否则“为什么差评变多”会被“为什么”带偏到无关评测。

### 3.3 向量

默认 `hash-512`：把 token 哈希到 512 维、带符号累加后 L2 归一化。零依赖、可复现，
但只有词面泛化能力。设置 `GRA_BGE_MODEL` 指向 `bge-small-zh-v1.5` 后重新构建，
`dense.py` 会自动改用 sentence-transformers 编码，接口与索引格式不变。

## 4. Agent 路由

路由优先由 LLM 完成：模型只输出结构化字段，不生成数字或原文。

```json
{"intent":"review","phases":["before","after"],"item_ids":["S15_01"],
 "language":"chinese","ranking":null,"confidence":0.9}
```

- `intent`：`metric / announcement / review / why / mixed / ranking / outside / need_context`
- `phases`：`before / release / after` 的**集合**；“更新前后”必须同时给 `before` 和 `after`
- `item_ids`：只能从当前版本的官方改动目录里选
- `ranking`：`{"metric_phase":"before|release|after","direction":"top|low|rise|drop"}`，
  只有明确的跨版本比较才给，`整体/全部语言` 属于语言分组，不是排行

LLM 超时、返回非法 JSON 或未配置 Key 时，退回同一套字段的确定性规则；规则覆盖
“哪个版本/全组/排名”“最高/最低 + 版本”“更新前后”“中文/英文”等常见说法。
版本号解析仍走规则（`1.12`、`Deep Freeze`、`7.33`），不让模型改错版本。

```
问题
 ├─ outside → 直接拒答
 ├─ ranking → 按 ranking.metric_phase 选 before/release/after 指标排序
 ├─ 能定位版本 → metric / announcement / review / why / mixed
 └─ 定位不到版本 → need_context（列出可选版本）
```

`why` 是特意分开的：问“为什么差评变多”时，按文本相关度检索容易抓到玩梗评论，
改成“对应阶段点赞最高的差评”更接近人想看的东西；有多条改动时，每条各自给证据或空态。

### 证据分级

有了上游版本分析模块的 469 条已复核引文后，检索结果分三级，Agent 按级别决定用谁：

1. `verified_quotes`：该版本有已复核库且命中 → 只用已复核引文，`citations[].verified=true`；
2. `dataset_quotes`：该版本没有已复核库，或“为什么差评多”需要代表性差评 → 用数据集原文，
   答案标题写“数据集原文（未复核）”，`verified=false`；
3. `none`：该版本有已复核库但这条改动没有可引用原话 → 直接返回空态，**不降级到未复核原文**。

这样“已复核”三个字不会被滥用：页面上只要出现 `verified=true`，就一定是那 469 条里的原文。

### 同义词层

官方标题和玩家说法经常对不上（“海浪” vs “海浪与水面改版”、“挂件” vs “武器吊饰”）。词典分两层：

- 条目层：`data_sources/lexicon/items_extra.jsonl`，每个条目 8–12 个同义词 + 3–6 个负向词，
  由人工重点词和模型批量扩词组成，构建时并入条目 BM25 索引，并参与命中门槛；
- 全局层：`data_sources/lexicon/global_synonyms.json`，把“闪退/崩溃/crash”“卡顿/掉帧”等
  归到同一组，查询时扩展，避免同一意思换个词就检索不到。

负向词用来防误命中（“外挂”不能命中“武器挂件”），但只在没有正向词时硬排除；
一个问题同时提到两个改动时，两个条目都可以成为候选。

独立评测 `eval/run_lexicon_eval.py` 覆盖同义、繁体、英文、错字和负向问法，当前 Hit@1 = 39/39。

## 5. 防幻觉的四条硬规则

1. 数字只能来自 `catalog.metrics`，模板里不出现任何手写数值；
2. 原话只能来自检索结果，`review_id` 和 Steam 链接随引用一起返回；
3. 检索不到 → `evidence_status=none` + “暂无已复核引文”，不拿常识补；
4. 缺版本 → `need_context`，不猜一个版本回答。

## 6. 验收

`eval/acceptance.jsonl` 43 题，覆盖：

- 指标：推荐率、样本量、方向（升/降）、中文/英文分组、发布当天、全组排行（8 题）
- 公告：条目数量、条目内容、10 项完整列出（3 题）
- 原文：已复核条目（姜岛 / 军械库 / 土地庙 / 海滩农场）、无证据空态（5 题）
- 回归：条目相关度门槛（海浪不串到拖船）、语言筛选、阶段筛选、带页面版本的排行（4 题）
- 归因：差评原因、链接完整性（2 题）
- 边界：超范围拒答、缺版本、版本不存在（3 题）
- 交叉：其他游戏版本、推荐率变化（2 题）

`eval/run_acceptance.py` 除了比对文字，还会检查：

- 每个数字与指标表的误差（推荐率 ±0.05pp，样本量精确）；
- 每条 `review` 引用的 URL 必须是 `https://steamcommunity.com/...`；
- 每条 `announcement` 引用必须有官方链接；
- 已复核类用例里，所有 `review` 引用必须 `verified=true`；
- 回归用例会检查引文的 `language_std`、`phase`、`item_id` 是否与请求一致；
- 差评归因里不允许出现“推荐”的引文。

当前结果：**43/43 通过**，见 `eval/REPORT.md`。
